Peppol integration blueprint (KBC‑style status, multi‑tenant, Belgium‑ready)
You’re basically building what banks expose as a “feature”—but as your own backbone. Let’s design it cleanly so BillGen can plug Peppol in once and reuse it across web, desktop, and mobile.

1. High‑level architecture
Components
BillGen Core API

Your main backend (Node/Python/Go)

Owns tenants, invoices, Peppol status, and business logic.

Peppol Access Point API

e.g. e‑invoice.be Peppol API—JSON in, UBL out, certified AP. 

Frontends

Web (React/Vite)

Desktop (Tauri)

Mobile (Tauri Mobile or React Native)

Data flow (send)
User creates invoice in BillGen.

BillGen validates business rules and stores invoice.

BillGen calls Peppol AP:

POST /api/documents with JSON invoice.

Store returned document_id.

BillGen calls:

POST /api/documents/:id/send to route via Peppol. 

Peppol AP processes, validates BIS 3.0, serializes to UBL, routes to recipient.

BillGen polls or receives webhook events and updates internal status timeline.

Data flow (receive)
Supplier sends invoice to your customer via Peppol.

Peppol AP receives and pushes signed webhook to BillGen. 

BillGen:

Verifies signature.

Stores inbound invoice.

Links to tenant/customer.

Frontends show “New Peppol invoice received” with full timeline.

3. Status timeline (like KBC’s app)
The AP exposes a per‑document timeline of every state change. 

3.1. Internal status model
Define a normalized status enum:

created — JSON accepted by AP.

validated — BIS 3.0 checks passed.

serialized — UBL XML generated.

routed — handed to recipient AP.

delivered — delivered to recipient inbox.

failed — any error (validation, routing, etc.).

3.2. Timeline table
Table: invoice_status_events

id (PK)

invoice_id (FK → invoices)

peppol_document_id (string)

status (enum)

source ("peppol" / "system" / "user")

message (text, optional)

created_at (timestamp)

Every webhook or poll result becomes an event row. Frontends simply render the ordered list.

3.3. Frontend component
Vertical stepper:

Created → Validated → Sent → Delivered

Each step:

Label: status

Timestamp: from invoice_status_events

Details: message (e.g. “Recipient AP: X, Participant ID: Y”)

4. Multi‑tenant SaaS design

Admin creates tenant in BillGen.

“Create tenant” / “Register customer on Peppol”.

AP returns:

Tenant API key

Every call to AP uses:

Org API key + Tenant API key (depending on provider).

Your backend middleware:

Reads tenant_id from JWT/session.

Injects correct Peppol credentials into outbound requests.

6. Backend implementation sketch
6.1. Sending invoice (pseudo‑Node)
ts
async function sendInvoiceToPeppol(invoiceId: string, tenantId: string) {
  const tenant = await db.tenants.findById(tenantId);
  const invoice = await db.invoices.findById(invoiceId);

  const payload = mapInvoiceToPeppolJson(invoice, tenant);

  const doc = await peppolClient.createDocument(payload, tenant.peppol_tenant_key);
  await db.invoices.update(invoiceId, { peppol_document_id: doc.id });

  await db.invoice_status_events.insert({
    invoice_id: invoiceId,
    peppol_document_id: doc.id,
    status: "created",
    source: "peppol"
  });

  await peppolClient.sendDocument(doc.id, tenant.peppol_tenant_key);

  await db.invoice_status_events.insert({
    invoice_id: invoiceId,
    peppol_document_id: doc.id,
    status: "sent",
    source: "peppol"
  });

  // Optionally poll or rely on webhook for delivered status
}
6.2. Webhook handler (receive + status updates)
ts
app.post("/webhooks/peppol", async (req, res) => {
  const signatureValid = verifyPeppolSignature(req);
  if (!signatureValid) return res.status(401).end();

  const event = req.body;

  if (event.type === "document_status_changed") {
    await db.invoice_status_events.insert({
      invoice_id: event.invoice_id,
      peppol_document_id: event.document_id,
      status: event.status,
      message: event.message,
      source: "peppol"
    });

    await db.invoices.update(event.invoice_id, {
      peppol_status: event.status
    });
  }

  if (event.type === "document_received") {
    // Create inbound invoice
    const invoiceId = await createInboundInvoiceFromPeppol(event);
    await db.invoice_status_events.insert({
      invoice_id: invoiceId,
      peppol_document_id: event.document_id,
      status: "received",
      source: "peppol"
    });
  }

  res.status(200).end();
});

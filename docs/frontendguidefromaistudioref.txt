7.6 Inconsistencies detected
Token inconsistencies

Referenced tokens include:

--bg-muted
--bg-border
--bg-card
--bg-text
--bg-text-secondary
--bg-app-shell

while the inspected token set primarily defines:

--bg-ink

--bg-surface
--bg-surface-alt

These should be reconciled into one canonical semantic-token vocabulary.

Undefined/possibly stale brand token

The component CSS references:

--brand-green-300

while the inspected brand palette contains emerald tokens rather than that exact green token.

This should be audited.

Icon-language inconsistency

The application simultaneously uses:

Lucide
custom SVG
emoji

For an enterprise SaaS, this creates three visual grammars.

Navigation duplication

There are effectively two sidebar systems:

SidebarNav
inline sidebar implementation inside App.tsx

There is also:

TopNav
mobile navigation implemented directly inside App.tsx

This indicates partial component-system abstraction.

Application-shell duplication

There is a reusable:

AppShell

but the actual main application shell is constructed directly inside:

App.tsx

Therefore AppShell appears to be a reusable architectural component that is not the primary shell implementation.

Settings-shell abstraction

Most important architectural conclusion: the uploaded frontend is already substantially more than a simple invoice-generator UI. It has a recognizable enterprise SaaS design system + invoicing domain model + administration layer + financial analytics layer. However, the implementation currently mixes a mature reusable component library with page-level Tailwind implementations, emoji/custom/Lucide iconography, multiple token vocabularies, and several enterprise areas that are represented structurally but not yet at the depth expected from a fully finished SaaS.

This inventory is therefore suitable as a baseline master component tree for comparing BillGen's current frontend against the demo and identifying missing/duplicated UI pieces.
